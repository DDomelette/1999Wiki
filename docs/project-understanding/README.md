# 项目理解文档

本目录用于沉淀“当前项目实际如何工作”的说明，帮助维护者在不通读全部源码和历史设计稿的情况下，建立可验证的系统认知。

这里的文档遵循以下约定：

- 以当前代码、配置和可复现测试为“现状事实”。
- 以 `docs/superpowers/specs/` 中仍有效的 spec 为“目标契约”。
- 当两者不一致时，明确标记为“部分实现”“未完成验收”或“设计漂移”，不把设计稿内容写成已实现事实。
- 结论尽量附代码入口、测试或评测报告，方便继续追踪。
- 文档只解释现状；新需求和实施方案仍分别进入 specs 与 plans。

## 建议的维护方式

出现下列变化时，应同步更新对应理解文档：

1. 生产入口、核心数据契约或路由规则发生变化。
2. spec 的主版本或验收口径发生变化。
3. 新的真实全链路评测推翻了文档中的状态判断。
4. 旧兼容路径被删除，或新的运行时路径替代现有路径。

更新时优先修改“快照与结论”“spec 对齐矩阵”“风险清单”和“验证证据”，并保留结论所依据的报告路径。
