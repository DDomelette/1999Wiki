# 聊天推荐问题栏设计

## 目标

在聊天输入框上方增加一栏推荐问题，让不知道如何提问的用户可以获得灵感。推荐项只把问题填入输入框，不直接发送，用户可以继续编辑后再提交。

## 范围

- 仅修改 React 前端，不增加后端接口或持久化数据。
- 在前端维护一个约 10–12 条的少量精选问题题库，覆盖人物、心相、剧情、世界、阵营和日历等现有检索主题。
- 聊天页面首次挂载时，从题库中无重复随机抽取 4 条；本次页面停留期间保持不变。
- 清空对话、切换检索范围或发送消息均不重新抽取，避免推荐项在用户阅读时突然变化。

## 组件与数据流

新增独立的 `SuggestedQuestions` 组件，负责题库、随机抽取和推荐按钮渲染。组件通过 `onSelect(question)` 回调把选择结果交给 `ChatInput`，不直接依赖聊天 store 的发送方法。

`ChatInput` 持有现有输入值，并在收到推荐问题时：

1. 用完整问题替换当前输入框内容；
2. 将焦点移到输入框；
3. 不触发发送，等待用户修改或确认。

推荐栏放在输入表单内部、文本输入行上方，因此始终紧邻输入框，也不会侵占消息滚动区。现有路由模式按钮仍保留在输入行下方。

## 视觉与响应式行为

- 推荐栏沿用现有羊皮纸主题变量，使用半透明背景、细边框和胶囊式问题按钮。
- 左侧显示简短标签“试着问问”，右侧横向排列 4 个问题。
- 宽屏优先在一行内展示；空间不足时问题区域横向滚动，不换成多行挤压消息区。
- 推荐按钮具有清晰的 hover、focus-visible 和 disabled 状态。
- 聊天发送期间推荐按钮禁用并降低透明度；发送完成后恢复。
- 明暗主题均只使用现有 CSS 变量，避免硬编码只适用于单一主题的颜色。

## 无障碍与边界行为

- 推荐区使用带可访问名称的分组语义。
- 每条推荐都是原生 `button`，支持键盘 Tab 和 Enter/Space 操作。
- 随机抽取函数在题库少于 4 条时返回所有可用问题，不重复、不报错。
- 选中推荐问题会覆盖输入框中尚未发送的草稿，这是明确且可预测的单击行为。

## 测试与验收

- 单元测试验证随机抽取结果不重复、数量上限为 4，并覆盖小题库边界。
- 组件测试验证空对话与已有消息时推荐栏都存在。
- 组件测试验证点击推荐问题只填入输入框并聚焦，不调用发送方法。
- 组件测试验证发送中所有推荐按钮均被禁用。
- 运行 React 前端相关 Vitest 测试和 TypeScript/Vite 构建。
- 在桌面宽屏与窄屏视口做视觉检查，确认推荐栏位于截图红框区域、不会遮挡输入框或模式按钮，并在窄屏可横向滚动。

## 非目标

- 不根据检索范围切换题库。
- 不调用模型或后端动态生成问题。
- 不记录推荐问题点击分析数据。
- 不在本次实现中加入“换一批”按钮或自动轮播。
