# 聊天推荐问题栏设计

## 1. 背景与目标

当前聊天页只提供空状态说明和自由输入框。用户不了解资料覆盖范围时，容易因不知道如何起问而中断使用。

本设计在聊天输入框上方增加常驻推荐问题栏，从少量精选题库中随机展示 4 条问题。推荐项只用于填充草稿，不直接发送，使用户既能获得灵感，也能在提交前继续修改。

## 2. 总体架构

功能只位于 React 前端，不新增后端接口、持久化数据或聊天 store 字段：

```text
本地精选题库
    │ 首次挂载时无重复抽样
    ▼
SuggestedQuestions
    │ onSelect(question)
    ▼
ChatInput 草稿状态 ── 用户修改/确认 ──► 既有 send(question)
```

关键技术栈为 React 18、TypeScript、Zustand、CSS 自定义属性、Vitest 和 Testing Library。推荐组件负责内容抽样与选择事件，`ChatInput` 继续负责草稿和发送，既有 `chatStore.send` 不感知推荐来源。

## 3. 推荐内容与抽样模块

### 3.1 模块职责

该模块维护精选问题题库，在组件首次挂载时生成一个稳定、无重复的推荐集合。

- 依赖：前端内置题库、`Math.random`。
- 输出：最多 4 条字符串形式的推荐问题。
- 边界：不读取检索范围，不访问后端，不修改聊天状态。

### 3.2 P0 当前必须满足

- `SUGGEST-P0-01`：前端维护 10–12 条精选问题，覆盖人物、心相、剧情、世界、阵营和日历等既有检索主题。
- `SUGGEST-P0-02`：页面首次挂载时从题库无重复随机抽取 4 条；题库不足 4 条时返回全部可用项且不报错。
- `SUGGEST-P0-03`：同一次组件挂载期间推荐集合保持稳定；编辑草稿、发送消息、清空对话或切换检索范围均不得自动重新抽样。

### 3.3 P1 可部分支持

- `SUGGEST-P1-01`：后续可增加用户主动触发的“换一批”，但不得自动轮播或在用户阅读时自行变化。本轮不实现。

### 3.4 P2 未来演进

- `SUGGEST-P2-01`：根据检索范围、会话上下文或热门内容动态推荐。
- `SUGGEST-P2-02`：由后端或模型生成推荐问题。

### 3.5 关键契约与限制

- 抽样不得修改原题库，也不得返回重复项。
- 抽样逻辑应是可独立测试的纯函数，并允许测试注入确定性随机源。
- 题库仅存放可直接提交给现有问答接口的完整中文问题。

## 4. 输入交互模块

### 4.1 模块职责

该模块把推荐选择接入现有受控输入框，同时保留原有发送、重试和检索模式行为。

- 依赖：`SuggestedQuestions` 的 `onSelect(question)` 回调和 `chatStore.sending`。
- 输出：更新后的输入草稿与输入框焦点。
- 边界：选择推荐问题不调用 `send`，不修改检索模式和分类。

### 4.2 P0 当前必须满足

- `INPUT-P0-01`：点击推荐问题后，用完整问题替换当前未发送草稿，并把键盘焦点移到输入框。
- `INPUT-P0-02`：选择推荐问题不得自动发送；只有用户提交现有表单后才调用既有 `send(question)`。
- `INPUT-P0-03`：推荐栏在空对话和已有消息时均常驻；发送期间所有推荐按钮禁用，发送结束后恢复。
- `INPUT-P0-04`：推荐功能不得改变现有发送、重试、扩大检索、自由补充和清空对话流程。

### 4.3 P1 可部分支持

- `INPUT-P1-01`：后续可在覆盖草稿前提供撤销或恢复旧草稿能力。本轮只采用明确的单击覆盖行为。

### 4.4 P2 未来演进

- `INPUT-P2-01`：记录推荐问题曝光、选择和最终发送的分析事件。

### 4.5 关键契约与限制

- `SuggestedQuestions` 只通过回调上报字符串，不直接依赖 Zustand store。
- 推荐按钮必须显式使用 `type="button"`，避免位于表单内时触发提交。
- 发送中状态以现有 `chatStore.sending` 为唯一来源。

## 5. 展示与无障碍模块

### 5.1 模块职责

该模块把推荐栏放入截图红框对应区域，并保证宽屏、窄屏、明暗主题和键盘操作均可用。

- 依赖：现有主题 CSS 变量和 `ChatInput` 表单布局。
- 输出：标签“试着问问”与 4 个胶囊式问题按钮。
- 边界：不改变消息滚动区高度计算，不引入新的主题色值或动效库。

### 5.2 P0 当前必须满足

- `UI-P0-01`：推荐栏位于输入表单内部、文本输入行上方，始终紧邻输入框且不遮挡发送按钮和检索模式按钮。
- `UI-P0-02`：宽屏时标签与推荐项优先单行排列；窄屏空间不足时推荐列表可横向滚动，不通过多行按钮持续挤压消息区。
- `UI-P0-03`：背景、边框、文字和交互状态只使用现有主题变量或基于主题变量的 `color-mix`，在 `manuscript-gold` 与 `storm-dark` 下均可辨认。
- `A11Y-P0-01`：推荐区具有“推荐问题”可访问分组名称；每项为原生按钮，支持 Tab、Enter 和 Space，并具备可见的 `focus-visible`、hover 与 disabled 状态。

### 5.3 P1 可部分支持

- `UI-P1-01`：后续可为横向溢出增加渐隐提示或滚动控制按钮。本轮依赖浏览器原生横向滚动。

### 5.4 P2 未来演进

- `UI-P2-01`：推荐项进入、切换或个性化排序动效。

### 5.5 关键契约与限制

- 响应式断点使用前端现有 CSS 媒体查询方式，不增加 JavaScript 视口监听。
- 发送中按钮降低视觉强调但仍保持文字可读。
- 推荐列表横向滚动不得传播为页面纵向滚屏操作的阻断逻辑。

## 6. 跨模块数据流

1. `SuggestedQuestions` 首次挂载，调用纯抽样函数从本地题库取得 4 条推荐。
2. 组件把推荐集合保存在挂载期状态中，并渲染为 `type="button"` 的原生按钮。
3. 用户选择某项后，组件调用 `onSelect(question)`。
4. `ChatInput` 替换受控草稿并聚焦输入框，不调用发送函数。
5. 用户修改或确认后提交既有表单，沿用原有 `chatStore.send` 数据流。
6. `chatStore.sending` 为真时，推荐按钮禁用；恢复为假时重新可用，但推荐集合不变化。

## 7. 错误处理原则

- 空题库或不足 4 条不应抛错：渲染所有可用项，空题库则渲染空列表并保留输入流程。
- 点击处理只更新本地草稿和焦点，不产生需要单独捕获的网络错误。
- 推荐功能异常不得阻断输入框、发送按钮或现有聊天链路。
- 本轮不为推荐内容增加后端 fallback，因为不存在远程依赖。

## 8. 测试与验收方向

- `SUGGEST-P0-01`：静态检查题库数量与主题覆盖。
- `SUGGEST-P0-02`：纯函数单测验证最多 4 条、不重复、不修改原数组及小题库边界。
- `SUGGEST-P0-03`：组件重渲染测试验证推荐集合保持稳定。
- `INPUT-P0-01`、`INPUT-P0-02`：交互测试验证覆盖草稿、聚焦且不调用 `send`。
- `INPUT-P0-03`：空/非空会话渲染测试与发送中 disabled 测试。
- `INPUT-P0-04`：运行既有 `ChatSection` 和前端完整测试套件。
- `UI-P0-01` 至 `A11Y-P0-01`：桌面 2048×1157、窄屏 390×844，以及明暗主题真实浏览器视觉与键盘验收。
- 完成前必须同时通过相关 Vitest、完整前端 Vitest、TypeScript/Vite 构建和真实页面验收；不能只凭单测宣称完成。

## 9. 与旧方案的关系

- 保留：现有 `ChatInput` 受控输入、`chatStore.send`、发送/重试流程、检索模式按钮、分类筛选和消息滚动区。
- 新增：独立的推荐题库/抽样/展示组件，以及 `ChatInput` 的选择回调和输入 ref。
- 废弃：无。推荐功能为现有输入工作流的前置辅助，不替换任何旧链路。
- 本轮明确不做：按分类推荐、模型生成、用户分析、“换一批”、自动轮播和推荐动效。
