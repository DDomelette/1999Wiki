# 1999Wiki 首屏加载性能修复设计

## 背景

生产环境首页在弱网下只显示全局背景，React 界面长时间不出现。服务器首页、就绪接口和业务 API 响应均正常，瓶颈位于前端首次加载：

- 入口 JavaScript 约 508 KiB，Caddy 未启用传输压缩。
- 首页立即请求约 117 MiB 的 `public/videos/pv.mp4`。
- 视频的 `moov` 元数据位于文件末尾，不利于网络流式启动。
- 两个中文 OTF 字体合计约 50 MiB。
- 静态资源没有显式的分层缓存策略。

## 目标

1. 背景加载后，导航、标题和首屏操作界面不等待视频即可出现并可交互。
2. 首页视频保留，但只作为渐进增强资源，不再阻塞首屏。
3. 显著减小视频和中文字体的网络传输体积，同时保留动态 Wiki 中文内容的完整字形覆盖。
4. 为可压缩资源启用 zstd/gzip，并为带哈希和不带哈希的静态资源配置正确缓存策略。
5. 使用新的不可变镜像标签部署到 Green；验证通过后切流，当前 Blue 保留为即时回滚版本。

## 方案比较

### 方案 A：渐进增强媒体（采用）

首屏始终先渲染背景图和 React 界面；浏览器进入空闲阶段后再挂载视频，视频使用 `preload="none"`，加载成功后淡入。视频重新编码并设置 faststart。中文字体转换为完整字形覆盖的 WOFF2。

优点是保留现有视觉效果，同时解决弱网首屏不可用问题；代价是视频会在界面出现后稍晚开始播放。

### 方案 B：彻底移除视频和自托管中文字体

仅使用背景图和系统中文字体。首屏最轻，但会明显改变现有设计，不符合保留首页动态背景的目标。

### 方案 C：媒体迁移到 CDN/COS

应用镜像减小，但服务器运行期需要访问或依赖外部媒体地址，与“服务器不依赖 COS、运行所需媒体尽量本地化”的既定部署边界冲突，因此本轮不采用。

## 前端行为设计

`HomeSection` 在首次渲染时只包含背景、内容和交互控件，不创建带 `src` 的视频请求。视频加载触发条件按以下顺序选择：

1. 浏览器支持 `requestIdleCallback` 时，在空闲回调中启用视频。
2. 不支持时，使用短延时回退，确保 React 首次绘制先完成。
3. 组件卸载时取消空闲回调或计时器，避免卸载后的状态更新。

视频启用后才渲染 `<video>`，并满足：

- `preload="none"`；
- `muted`、`loop`、`playsInline` 和自动播放行为保持不变；
- 全局背景图继续作为 poster 和永久回退层；
- `canplay` 后淡入；
- 加载失败只保留背景，不影响首屏内容；
- 用户启用减少动态效果偏好时不加载视频。

这使“首屏可交互”和“媒体可播放”成为两个互不阻塞的阶段。

## 媒体与字体设计

### 视频

保留一个服务器本地 MP4，使用 H.264、兼容性像素格式和受控码率重新编码，并添加 `faststart`。验收要求：

- `moov` 位于 `mdat` 之前；
- 文件体积不超过 20 MiB；
- 浏览器可通过 Range 请求播放；
- poster 始终可用，视频失败不影响页面内容。

编码优先保持现有画面比例；分辨率最高 1920×1080，帧率最高 30 fps。音频对静音背景视频无用途，编码时移除。

### 字体

动态 Wiki 文本无法安全地按当前源码字符子集化，因此不做会造成缺字的字形裁剪。两个 Noto Serif SC 字重保留完整中文覆盖并转换为 WOFF2，CSS 使用 `format("woff2")` 和 `font-display: optional`。其余三个体积较小的拉丁/等宽字体保持现状。

验收要求：

- 不再由 CSS 引用两个 OTF；
- 两个 WOFF2 文件均可被字体解析工具读取；
- WOFF2 合计体积小于原 OTF 合计体积；
- 动态中文内容仍有完整字形回退链，即使字体下载失败也可使用 `Songti SC` 或系统 serif。

## Caddy 传输与缓存设计

Caddy 为文本类资源启用 `zstd gzip`。缓存按资源身份分层：

- `/assets/*`：Vite 文件名带内容哈希，使用 `Cache-Control: public, max-age=31536000, immutable`。
- 字体、图片和视频：使用 `Cache-Control: public, max-age=604800`，允许一周缓存和 ETag 再验证。
- `index.html` 及 SPA 回退响应：使用 `Cache-Control: no-cache`，确保新版本入口及时更新。
- API 与健康检查保持反向代理行为，不添加静态资源缓存头。

服务器继续支持 Range 请求，视频响应不得被压缩。

## 测试与验收

### 自动化测试

1. `HomeSection` 初始渲染不存在视频元素或视频源请求。
2. 空闲回调触发后才出现视频，且 `preload="none"`。
3. `canplay` 后视频淡入，错误后视频移除但内容保留。
4. 减少动态效果偏好下不加载视频。
5. 字体 CSS 只引用 WOFF2 中文字体并保持系统回退。
6. Caddy 配置包含压缩、三层缓存策略和现有 API 代理规则。
7. 媒体审计脚本验证视频体积上限和 `moov`/`mdat` 顺序。

### 构建与运行验证

- 前端单元测试全部通过。
- TypeScript 和 Vite 生产构建通过。
- 新前端镜像通过容器健康检查。
- Green 环境首页、`/wiki`、API 和健康接口冒烟通过。
- HTTP 响应确认 JS/CSS 使用 zstd 或 gzip，哈希资源具有 immutable 缓存，入口 HTML 为 no-cache。
- 弱网模拟下先出现可交互 UI，视频随后加载；视频失败时 UI 仍保持可用。

## 发布与回滚

1. 生成新的 `sha-<commit>` 后端与前端镜像标签，后端即使代码未变也保持同一发布身份。
2. 同步发布到 GHCR 与 TCR；服务器优先从 TCR 拉取。
3. 将新版本部署到 Green，不覆盖当前 Blue。
4. 完成容器健康、HTTP、API、缓存头和浏览器首屏验证后切换入口。
5. 切换后继续保留当前 Blue；若出现缺字、视频播放或页面初始化问题，立即切回 Blue。

## 非目标

- 本轮不接入 CDN，不改变 COS 备份定位。
- 不改变后端、MySQL、Milvus、MinIO 的运行结构。
- 不重做首页视觉设计，也不移除现有背景视频。
- 不对 Wiki 动态中文字符做不可逆的激进子集裁剪。
