# 图片画廊交互调整设计

## 目标

修复聊天图片画廊的三个交互问题：

1. 全屏图片查看器的关闭按钮不得被悬浮导航遮挡。
2. 上一张、下一张按钮不得因文件名长度变化而移动。
3. 桌面端与移动端均应支持自然的横向切图，并在松手后以可感知、非闪现的动画吸附到最近图片。

本次只调整现有 `CircularGallery` 及其测试，不改变媒体数据格式、聊天消息结构或站点导航。

## 已确认的交互

- 桌面鼠标使用 `Shift + 滚轮` 横向切换图片。
- 触控板原生横向滚动可切换图片。
- 普通纵向滚轮不被画廊拦截。
- `Ctrl + 滚轮` 保留浏览器缩放，不被画廊拦截。
- 移动端横向拖动时图片跟随手指位移。
- 松手后综合拖动距离和释放速度决定切到上一张、停留当前张或切到下一张。
- 如果松手位置处于两张图之间，图片自动吸附到目标图片的中心位置。
- 吸附使用线性动画；动画时长根据剩余距离计算并限制在合理区间，避免闪现、过快或拖沓。
- 系统启用减少动态效果时，省略吸附过渡并立即准确落位。

## 根因

### 关闭按钮被遮挡

全屏查看器当前渲染在聊天区域内部。聊天区域使用 `backdrop-filter`，会创建独立层叠上下文；因此查看器自身的 `position: fixed` 和较高 `z-index` 仍无法越过页面级悬浮导航。

### 导航按钮换位

左右按钮、可变宽文件名和放大按钮目前处在同一个水平居中的 flex 容器中。文件名宽度变化会改变整个控件组的宽度，进而改变左右按钮的绝对屏幕位置。

### 缺少连续拖动

现有实现只监听横向滚轮，并在节流后直接更改当前索引。它没有维护拖动位移、释放速度或吸附状态，因此触摸横滑无法跟手，也无法在两张图之间平滑落位。

## 方案

### 全屏查看器

使用 React Portal 将全屏查看器挂载到 `document.body`：

- 彻底脱离聊天区域的层叠上下文。
- 遮罩层位于悬浮导航之上。
- 关闭按钮固定在视口右上区域，纵向位置同时避开悬浮导航栏，横向位置加入 `env(safe-area-inset-right)`；查看器仍位于导航之上，确保导航展开等异常状态下按钮也能命中。
- 全屏图片的最大宽高扣除安全边距，避免关闭按钮与图片内容重叠。
- 保留点击遮罩关闭、Escape 关闭以及关闭后焦点回到放大按钮的行为。

### 固定导航按钮

将控件拆成三个位置稳定的区域：

- 上一张按钮绝对定位在图片视口左侧中央。
- 下一张按钮绝对定位在图片视口右侧中央。
- 文件名、序号和放大按钮保留在底部信息栏；文件名使用截断显示。

左右按钮拥有固定尺寸和固定边距，不参与文件名的宽度计算。到达首尾时按钮保持原位并显示禁用状态，避免界面跳动。

### 拖动与吸附

画廊增加一个独立的拖动状态模型：

- 指针按下时记录起始横坐标、起始时间和当前索引。
- 指针移动时计算水平位移，并通过 CSS 自定义属性实时偏移当前、上一张和下一张图片。
- 在第一张继续右拖或最后一张继续左拖时加入阻尼，明确表达边界。
- 指针释放时计算拖动距离和速度。
- 位移达到视口宽度的约四分之一，或释放速度达到快速滑动阈值时，切换一张；否则回到当前图片。
- 目标索引始终限制在有效范围内。
- 吸附距离决定动画时长，时长限制在约 `180ms` 至 `420ms`，使用 `linear` timing function。
- 动画完成后清除临时拖动状态，只保留稳定的当前索引。

使用 Pointer Events 统一鼠标、触控笔和触摸操作，并设置 `touch-action: pan-y`，允许页面纵向滚动，同时由画廊处理明确的横向拖动。

### 滚轮与键盘

- `Shift + wheel`：将纵向滚轮增量映射为横向意图，并按方向切换一张。
- 触控板 `deltaX` 明显大于 `deltaY` 时按横向意图处理。
- `Ctrl + wheel`：立即返回，不调用 `preventDefault`。
- 普通纵向滚轮：立即返回，不调用 `preventDefault`。
- 保留现有按钮和点击相邻图片切换。
- 画廊获得焦点时支持左右方向键切换。

滚轮切换继续使用短节流，避免单次机械滚轮动作连续跨越多张图片。

## 状态与组件边界

交互状态保留在 `CircularGallery` 内部，不上移到聊天 store：

- `currentIndex`：稳定落位后的当前图片。
- `dragOffset`：拖动或吸附过程中的临时水平位移。
- `isDragging`：是否处于跟手阶段。
- `snapDuration`：本次吸附动画时长。
- 指针采样 ref：保存起点、最近位置和时间，不触发无意义的 React 重渲染。

纯计算逻辑提取为可单元测试的导出函数，例如目标索引判定、边界限制和吸附时长计算。DOM 组件只负责事件接线、状态更新与无障碍属性。

## 错误与边界处理

- 零张图片时所有切换入口均无操作，放大按钮禁用。
- 一张图片时左右按钮保持禁用，拖动只显示边界阻尼并回弹。
- 图片列表缩短时继续使用安全索引，避免索引越界。
- 指针取消、窗口失焦或组件卸载时清理捕获和临时拖动状态。
- 首尾快速滑动不得越界。
- 文件名为空时显示现有空字符串回退，不影响控件布局。

## 测试策略

### 单元与组件测试

在 `CircularGallery.test.tsx` 中先写失败测试，覆盖：

- 左右按钮位于独立的固定导航区域，不再与文件名同组。
- `Shift + wheel` 切换图片。
- `Ctrl + wheel` 和普通纵向滚轮不切换图片，也不阻止默认行为。
- 横向触控板滚动切换图片。
- 拖动超过距离阈值后切换。
- 快速短拖动可按速度阈值切换。
- 小幅慢拖动回到当前图片。
- 首尾拖动不越界。
- 查看器通过 Portal 渲染到 `document.body`。
- Escape、遮罩和关闭按钮仍能关闭查看器并恢复焦点。

纯计算函数分别覆盖阈值边界和吸附时长上下限。

### 端到端与视觉验证

新增或扩展 Playwright 场景，在桌面和移动端验证：

- 关闭按钮的矩形区域不与悬浮导航重叠，并且可以点击。
- 长短文件名切换前后，左右按钮的 `x/y` 坐标保持不变。
- 移动端拖动后当前图片发生变化并最终居中。
- 桌面 `Shift + wheel` 可以切换，`Ctrl + wheel` 不切换。
- 390×844、900×900、1440×900 视口下无溢出或按钮遮挡。

最终运行相关 Vitest、Playwright 场景、TypeScript 构建与 lint（若项目已有对应脚本），并人工检查桌面与移动端截图。
