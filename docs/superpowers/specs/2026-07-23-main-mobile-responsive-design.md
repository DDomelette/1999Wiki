# 生产 React 主页面移动端响应式优化设计

**状态：** 已批准  
**日期：** 2026-07-23  
**范围：** `frontend/react-app` 的生产主页面 `/`，包括首页、资料区和问答区

## 1. 背景

生产 React 主页面由 `HomeSection`、`DataSection` 和 `ChatSection` 三个全屏滚动区组成。当前顶部 Card Nav 和推荐问题组件有局部移动断点，但三个页面主体仍沿用桌面布局。

在 390×844 与 320×568 的真实浏览器视口中已确认以下问题：

- 资料页双栏最小宽度为 `320px + 560px`，390px 视口下内部横向内容约 979px，右侧图片离开首屏。
- 资料页左侧悬浮分类导航仍占据正文空间，没有手机端导航形态。
- 问答页顶部工具栏从视口 `top: 0` 开始，被固定 Card Nav 完整覆盖，分类、清空和返回控件无法点击。
- 320px 宽度下问答输入框不能收缩，发送按钮被裁切。
- 主页面使用固定 `100vh` 和强制整屏吸附，没有动态视口与安全区处理。

## 2. 目标

1. 为生产 React 的首页、资料区和问答区建立明确的手机端布局。
2. 保持桌面端视觉、数据流、状态管理、API、路由和会话行为不变。
3. 在 320px 宽手机上消除非预期横向溢出与不可点击控件。
4. 在手机浏览器动态工具栏和软键盘出现时保持页面可用。
5. 通过组件测试、CSS 契约、Playwright 和多视口截图建立可重复验收证据。

## 3. 非目标

- 不优化 `/wiki/*` 或 `/wiki-preview/*`。
- 不迁移或复用 `kimi_web` 独立原型运行时。
- 不修改后端、API DTO、Zustand Store、会话逻辑或手写路由。
- 不引入新的 UI 框架、CSS-in-JS 方案或重复的移动版业务组件。
- 不重做桌面端视觉风格。

## 4. 选定方案

采用“响应式样式层重构”：保留现有 React 组件树，为布局节点增加语义 class，将影响响应式布局的内联尺寸迁入就近 CSS。动态图片 URL、运行时颜色和 Framer Motion 动画参数继续保留在 JSX 中。

未采用纯 CSS 补丁，因为现有内联布局会迫使样式使用大量 `!important`。未采用独立移动组件，因为它会复制资料和问答行为并扩大桌面/手机漂移风险。

## 5. 文件边界

新增样式文件：

- `frontend/react-app/src/components/sections/HomeSection.css`：首页内容、竖屏视频定位、CTA 与滚动提示。
- `frontend/react-app/src/components/sections/DataSection.css`：资料区桌面双栏、移动海报布局、横向分类标签和 WIKI 入口。
- `frontend/react-app/src/components/sections/ChatSection.css`：问答工具栏、消息区、气泡、推荐问题、输入与安全区。

修改现有文件：

- `HomeSection.tsx`、`DataSection.tsx`、`CategoryPanel.tsx`、`ChatSection.tsx`、`ChatInput.tsx`、`MessageBubble.tsx`：增加语义 class，并移出影响布局的静态内联样式。
- `CardNav.css`：仅在 `.card-nav--main` 下增加紧凑移动规则，不改变 Wiki 导航。
- `global.css`：增加动态视口回退、移动滚动吸附策略和共享安全区变量。

测试文件：

- 修改现有 `HomeSection.test.tsx`、`CategoryPanel.test.tsx`、`ChatSection.test.tsx` 和 `ChatInput.test.tsx`。
- 新增 `frontend/react-app/src/components/sections/MainResponsiveCss.test.ts`。
- 新增 `frontend/react-app/e2e/main-mobile-responsive.spec.ts`。

## 6. 响应式架构

### 6.1 断点

- `> 980px`：保持现有桌面双栏与全尺寸导航。
- `≤ 980px`：资料区切换为海报叠层布局，覆盖竖屏平板。
- `≤ 720px`：首页、主导航和问答区进入手机布局。
- `≤ 360px`：进一步压缩标题、间距和次要操作，但不隐藏核心功能。

断点全部使用 CSS 媒体查询。布局不依赖 `window.innerWidth` 或 React 条件分支。

### 6.2 视口与滚动

`.snap-container` 和 `.snap-section` 先保留 `100vh` 回退，再声明 `100dvh`。手机端将主滚动吸附由 `mandatory` 降为 `proximity`，避免软键盘、内部消息滚动和浏览器地址栏变化触发强制跳页。

页面使用 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`。问答输入区吸收底部安全区；顶部内容通过共享移动导航高度避开 Card Nav。

## 7. 页面设计

### 7.1 首页

- 保留视频背景、海报回退、居中标题和下载 CTA。
- 手机端降低标题间距与 CTA 上边距，下载按钮保持至少 44px 的可点击高度。
- 视频使用竖屏 `object-position`，不改变 `object-fit: cover`。
- 滚动提示通过底部安全区定位。
- 仅缩小 `.card-nav--main`：视觉栏高约 38–40px，图标操作区约 36px；桌面与 Wiki Card Nav 不受影响。

### 7.2 资料区

移动端采用已批准的“电影渐变式 A-v2”方向：

- 每个分类仍是独立资料面板，但由桌面双栏改为单屏海报构图。
- 图片成为主视觉，宽高受视口约束并按分类设置定位，人物立绘靠右下，封面类图片保持主体可见。
- 标题、英文副题、数量和简介位于左下角，可适度覆盖图片。
- 文字区域不使用黑色背景块，只使用轻描边与柔和阴影保证可读性。
- 文本宽度在手机端控制在约 58%–64%，避免完全遮挡主体。
- 桌面左侧纵向分类导航在 `≤980px` 隐藏，替换为 Card Nav 下方可横向滑动的小标签。
- 标签视觉高度约 22–24px，实际点击区域至少 28px，不显示原生滚动条。
- “进入 WIKI”改为文字区附近的紧凑箭头入口，不压住图片主体。
- 图片加载失败时保留纹理背景、分类标题与说明，不出现空白面板。

### 7.3 问答区

- 顶部检索工具栏放在紧凑 Card Nav 下方，不能与固定导航重叠。
- 工具栏在手机端分为分类选择和清空/返回操作两组；必要时允许两行，但核心控件不得裁切。
- 消息气泡手机端最大宽度约 88%，长单词、链接、代码与表格不得扩大页面宽度。
- Markdown 代码块和表格在自身容器内横向滚动。
- 输入行使用 `grid-template-columns: minmax(0, 1fr) auto`，输入框显式 `min-width: 0`。
- 发送按钮和主输入控件保持至少 44px 高，在 320px 下完整可见。
- 推荐问题保持一行横向滑动，标签和按钮缩小，不强制把整个输入区撑宽。
- “扩大检索”和“自由补充”位于输入行下方，允许换行。
- 输入区包含底部安全区；动态视口缩小时，消息区收缩并继续独立滚动。

## 8. 可访问性与交互

- 保留现有按钮、选择框和表单的语义与 ARIA 标签。
- 导航图标操作区约 36px，分类标签实际点击区域至少 28px，CTA、输入框和发送按钮至少 44px 高。
- 所有移动控件必须通过真实浏览器 `elementFromPoint` 命中自身，而不是 Card Nav 覆盖层。
- 横向标签和推荐问题使用触摸横滑，并保留键盘焦点可见样式。
- 不以隐藏核心控件的方式解决空间不足。

## 9. Kimi CLI 协作与接管

Codex 负责需求、架构、失败测试、文件白名单、diff 审查、完整验证和最终验收。Kimi CLI 只负责批准视觉范围内的 JSX class 调整与 CSS 首轮实现。

Kimi CLI 的允许修改范围限于第 5 节列出的主页面组件、样式与对应测试。禁止修改 API、Store、路由、Wiki 页面、后端或构建依赖。

执行按首页、资料区、问答区分批进行。每批都必须先有失败测试，再允许 Kimi 修改，之后由 Codex 检查 diff 并运行聚焦测试。

当 Kimi CLI 返回额度耗尽、鉴权失败、非零退出、没有有效结果或中途停止时，Codex 保留已通过审查的局部改动并直接接管剩余实现，不等待额度恢复，也不重复覆盖用户已有改动。

## 11. 风险与控制

- **内联样式优先级：** 仅迁移布局相关静态属性，避免使用 `!important` 强压 JSX。
- **共享 Card Nav 回归：** 所有紧凑规则必须限定在 `.card-nav--main`。
- **不同分类图片比例：** 通过分类 data 属性或 modifier class 设置定位，不使用单一裁切参数覆盖所有图片。
- **滚动容器竞争：** 手机端主页面使用 `proximity`，资料标签、推荐问题和 Markdown 分别拥有明确的局部横向滚动所有权。
- **视觉优化破坏逻辑：** Kimi CLI 文件白名单和 Codex diff 审查阻止数据层、状态层和路由层漂移。
